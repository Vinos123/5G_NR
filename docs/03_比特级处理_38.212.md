# 03 · 比特级处理（步骤 1–7）：38.212 复用与信道编码

> 目标：把一坨 TB 比特，一步步变成「码字比特」，覆盖 38.212 §6.2.1–6.2.7。
> 配套 C++：`code/src/segmentation.cpp`、`code/src/ldpc.cpp`、`code/src/rate_match.cpp`、`code/src/pusch.cpp`。

---

## 3.1 步骤 1：TB CRC 附加（38.212 §6.2.1）

给 TB（A 比特）末尾加一段 CRC，用于收端检错。**长度由 A 决定**：

| 条件 | CRC | 多项式 g(D) | 长度 L |
|---|---|---|---|
| A > 3824 | CRC24A | D²⁴+D²³+D¹⁸+D¹⁷+D¹⁴+D¹¹+D¹⁰+D⁷+D⁶+D⁵+D⁴+D³+D+1 | 24 |
| A ≤ 3824 | CRC16 | D¹⁶+D¹²+D⁵+1 | 16 |

输出 `b(0..B-1)`，B = A + L。

> **全部四种 CRC 多项式（38.212 §5.1，记住这组常数）**：
> - CRC24A = `0x1864CFB`，CRC24B = `0x1800063`（码块 CRC），CRC24C = `0x1B2B117`（DCI），CRC16 = `0x11021`。

**C++**：`nrphy::crc()` / `crc_attach()`（`code/include/nrphy/crc.h`）。实现是 MSB-first 无反射的逐位 CRC，`crc(msg || parity) == 0` 可自检。

**数值实例**：单比特 `[1]` 的 CRC16 = `0x1021`（D¹⁶ mod g = D¹²+D⁵+1）；序列 `[1,0]` 的 CRC16 = `0x2042`。这是测试里的手工向量。

## 3.2 步骤 2：LDPC 基图选择（38.212 §6.2.2）

NR 数据信道用两个 LDPC 基图（Base Graph），**按 TB 大小 A 和目标码率 R 选一个**：

```
BG2  若  A ≤ 292  或  R ≤ 0.25  或  (A ≤ 3824 且 R ≤ 0.67)
BG1  否则
```

| | BG1 | BG2 |
|---|---|---|
| 尺寸（行×列） | 46×68 | 42×52 |
| 信息列 Kb | 22 | 10（可缩减到 9/8/6） |
| 母码率 | 22/66 = 1/3 | 10/50 = 1/5 |
| 最大 K | 8448 | 3840 |
| 适用 | 大 TB / 高码率 | 小 TB / 低码率 |

**C++**：`nrphy::select_base_graph(A, R)`（`segmentation.cpp`）。

---

## 3.3 步骤 3：码块分段 + 码块 CRC（38.212 §6.2.3）

### 3.3.1 lifting size（提升因子 Zc）

LDPC 基图是「模板」，实际码由 Zc 提升得到。Zc 有 **51 个取值**，分成 **8 套（set，i_LS = 0..7）**：

| i_LS | Zc 取值 |
|---|---|
| 0 | 2, 4, 8, 16, 32, 64, 128, 256 |
| 1 | 3, 6, 12, 24, 48, 96, 192, 384 |
| 2 | 5, 10, 20, 40, 80, 160, 320 |
| 3 | 7, 14, 28, 56, 112, 224 |
| 4 | 9, 18, 36, 72, 144, 288 |
| 5 | 11, 22, 44, 88, 176, 352 |
| 6 | 13, 26, 52, 104, 208 |
| 7 | 15, 30, 60, 120, 240 |

**关键机制**：基图移位值 V(i,j) 是**按 set 存储的**（8 套表），实际循环移位 `P(i,j) = V(i,j) mod Zc`。这点和 LTE 一致，别当成单一 V 矩阵。

### 3.3.2 分段算法

1. **码块数 C**：B ≤ Kcb（BG1=8448 / BG2=3840）→ C=1；否则 `C = ⌈B/(Kcb−24)⌉`（预留 24 比特码块 CRC）。
2. **缩减 Kb′**（仅用于选 Zc）：BG1 恒 22；BG2 按 B 分档 —— B>640→10，560<B≤640→9，192<B≤560→8，B≤192→6。
3. **选 Zc**：最小 Zc 使 `C·Kb′·Zc ≥ B + 24·C（若 C>1）`。
4. **码块长 K = Kb·Zc**（Kb 用**完整值** 22/10，不是缩减值！）。
5. **filler** = K − (info + CRC)，补 0 填满。

### 3.3.3 每个码块的内容布局

```
[ 数据 ][ TB CRC (仅末块) ][ 零填充 (仅末块) ][ CB CRC (仅 C>1) ][ filler 0 ]
```

- TB CRC 在**最后一个码块**里（数据末尾）。
- CB CRC（CRC24B）在 C>1 时每个码块都有，覆盖「数据 + TB CRC + 零填充」。
- filler 补到 K 比特，编码时参与、速率匹配时跳过。

**C++**：`nrphy::segment_tb()`（`segmentation.cpp`）。

**数值实例**（测试金标准）：TB=96、BG2 → C=1、Zc=20、K=10·20=200、filler=88。

## 3.4 步骤 4：LDPC 编码（38.212 §6.2.4 / §5.3.2）

### 3.4.1 基图 → 提升校验矩阵 H

基图每个非零项 V(i,j) 替换成 Zc×Zc 循环置换矩阵 I(P)，`P = V(i,j) mod Zc`；`-1` 替换成全零。得到的 H 是准循环（QC-LDPC）矩阵，尺寸 (Mb·Zc)×(Nb·Zc)。

### 3.4.2 编码三步（利用 eIRA 结构）

码字 = [信息列 0..Kb−1 ｜ 核心校验列 Kb..Kb+3 ｜ 扩展校验列 Kb+4..Nb−1]。前 2 列（信息列 0,1）**被打孔**（不发送）。

1. **信息累积**：对 4 个核心行 m=0..3，`aux[m] = ⊕ 各信息列(按移位循环)的信息比特`。
2. **核心校验**（4 块，双对角回代）：核心校验子矩阵的 0/1/105 移位结构随 i_LS 变化，分 4 种情形回代（见 `ldpc.cpp` 的 `BG1 i6 / BG1 other / BG2 i3,7 / BG2 other`）。
3. **扩展校验**（单对角）：每个扩展行 m=4..Mb−1，`p[m] = ⊕(信息列贡献) ⊕(核心校验列贡献)`，写到列 Kb+m。

输出码字 = 完整码块去掉前 2Zc 比特，长 `N = 66·Zc`（BG1）/ `50·Zc`（BG2）。

**C++**：`nrphy::ldpc_encode()`（`ldpc.cpp`）。

**验证**：测试里独立构建提升 H，校验 `H·cᵀ = 0`，覆盖两基图 × 18 个 Zc（含各种 i_LS 特殊情形）。

## 3.5 步骤 5：速率匹配（38.212 §6.2.5 / §5.4.2.1 + §5.4.2.2）

把编码输出 N 比特适配到实际分配的资源比特数 E。

### 3.5.1 环形缓冲

- `N_cb = min(N_ref, N)`（受限缓冲 LBRM 时 N_ref < N；否则 N_cb = N）。
- 起始位置 `k0 = ⌊(shift_factor[rv] · N_cb / N)⌋ · Zc`。

| rv | BG1 shift_factor | BG2 shift_factor |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 17 | 13 |
| 2 | 33 | 25 |
| 3 | 56 | 43 |

- 从 k0 起**环形**取 E 比特，**跳过 filler**（位于 systematic 部分末尾 `[20Zc−filler, 20Zc)`，BG1）。

### 3.5.2 位交织（§5.4.2.2，仅 16/64/256QAM）

Qm>2 时，速率匹配输出按 Qm 行 × K 列「写行读列」转置：符号 i 的第 j 位 = 输入第 `j·K+i` 位。QPSK/BPSK 不交织。

**C++**：`nrphy::rate_match()`（`rate_match.cpp`）。

---

## 3.6 步骤 6：码块级联（38.212 §6.2.6）

各码块的速率匹配输出 `e_r` 按原顺序拼接成 `f(0..G−1)`。收端据此再切分。

**C++**：`pusch_encode_bits()` 里的 `f.insert(...)`。

---

## 3.7 步骤 7：数据与控制复用（38.212 §6.2.7）

PUSCH 上 UCI（HARQ-ACK、CSI part1/part2）与 UL-SCH 数据按优先级复用进同一序列，并给 DMRS 留位。**纯数据 PUSCH 无此步**。参考实现先覆盖纯数据，UCI 复用留作扩展（见第 08 章）。

---

## 3.8 与卫星 SDR 对照

| 卫星/通用 | 5G NR |
|---|---|
| CRC（定长） | CRC 长度按 A 切换 16/24 |
| 单一 LDPC/Turbo 码 | 双基图 + 8 套移位 + 提升因子 Zc |
| 固定码块分段 | Kcb、缩减 Kb′、filler 精确到规范 |
| 打孔/重复速率匹配 | 环形缓冲 + RV 起点 + Qm 位交织 |

**一句话**：你熟悉的「CRC + 分段 + LDPC + 速率匹配」在 NR 里被参数化到了极致——每一步都有一张表/一个公式精确约束，这就是「读规范」要啃的东西。
