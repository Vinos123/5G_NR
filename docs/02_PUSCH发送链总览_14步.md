# 02 · PUSCH 发送链总览（14 步）

> 目标：把 PUSCH 从「一坨 Transport Block 比特」到「资源栅格上的调制符号」的完整流程一次性看全，建立全局。
> 锚点：sharetechnote [5G_PUSCH](https://www.sharetechnote.com/html/5G/5G_PUSCH.html)。对应 **38.212 §6.2（步骤 1–7）** 与 **38.211 §6.3.1（步骤 8–14）**。

---

## 2.1 一句话流程

> **TB（来自 MAC 的比特）→ 编码成码字 → 变成复数符号 → 摆到资源栅格 → 交给 OFDM 基带。**

规范把它切成两段，分别写在两本书：

- **比特级（步骤 1–7）**：在 **38.212**，输入 TB 比特、输出码字比特 `f(k)`。
- **符号级（步骤 8–14）**：在 **38.211**，输入码字比特、输出栅格上的复数符号。

---

## 2.2 完整数据流图

```
                38.212 (比特级)                                38.211 (符号级)
═══════════════════════════════                        ═══════════════════════════
 a(0)..a(A-1)  ← Transport Block (A 比特，来自 MAC)
      │
 [1] TB CRC 附加                      (6.2.1)  A>3824→CRC24A，否则 CRC16
      │  b(0)..b(B-1),  B = A+L
 [2] LDPC 基图选择                    (6.2.2)  BG1 或 BG2（由 B 和码率定）
      │
 [3] 码块分段 + 码块 CRC              (6.2.3)  大 TB 切成多块，每块 +CRC24B
      │  c_r0..c_r(Kr-1)
 [4] LDPC 编码                        (6.2.4)  每块→LDPC 码字 d_r
      │  d_r0..d_r(Nr-1)
 [5] 速率匹配                        (6.2.5)  环形缓冲，匹配到 E_r 比特
      │  e_r0..e_r(Er-1)
 [6] 码块级联                        (6.2.6)  各码块按顺序拼接
      │  f(0)..f(G-1)
 [7] 数据/控制(UCI)复用              (6.2.7)  UL-SCH 数据 + HARQ-ACK/CSI
      │  g(0)..g(G'-1)   ← 码字比特
 ─────┼─────────────────────────────────────────────────────────────┐
      │                                                              │
 [8] 加扰 scrambling                 (6.3.1.1)  b̃(i)=b(i)+c(i) mod2   │
 [9] 调制 modulation                 (6.3.1.2)  QPSK/16/64/256QAM      │
[10] 层映射 layer mapping            (6.3.1.3)  1 个码字→ν 层          │
[11] 变换预编码 transform precoding  (6.3.1.4)  DFT（仅 DFT-s-OFDM）  │
[12] 预编码 precoding                (6.3.1.5)  W·x（多天线端口）     │
[13] 映射到 VRB                     (6.3.1.6)  摆到虚拟资源栅格       │
[14] VRB→PRB 映射                   (6.3.1.7)  上行=恒等映射          │
      │                                                              │
      ▼                                                              │
   资源栅格上的调制符号  →  OFDM 基带生成 (38.211 §5.3)              │
═══════════════════════════════════                        ═══════════════════════════
```

> 括号里的 `(6.2.x)` / `(6.3.1.x)` 是精确的规范 clause 号——读规范时按这个顺序逐条读即可。

## 2.3 14 步速查表

| 步 | 名称 | 输入 → 输出 | 规范 clause | 关键点 |
|---|---|---|---|---|
| 1 | TB CRC 附加 | `a(A)` → `b(B)` | 38.212 §6.2.1 | A>3824 用 CRC24A，否则 CRC16 |
| 2 | LDPC 基图选择 | `b(B)` → 选 BG1/BG2 | 38.212 §6.2.2 | 由 B 和码率 R 查表选择 |
| 3 | 码块分段+CRC | `b(B)` → 各码块 `c_r` | 38.212 §6.2.3 | Kcb=8448(BG1)/3840(BG2)，每块 +CRC24B |
| 4 | LDPC 编码 | `c_r` → 码字 `d_r` | 38.212 §6.2.4 | 基图 + 提升因子 Zc |
| 5 | 速率匹配 | `d_r` → `e_r` | 38.212 §6.2.5 | 环形缓冲，凑够分配比特数 E_r |
| 6 | 码块级联 | `e_r` → `f` | 38.212 §6.2.6 | 按原顺序拼接 |
| 7 | 数据/控制复用 | `f` → `g` | 38.212 §6.2.7 | UCI(HARQ-ACK/CSI) 插到数据旁 |
| 8 | 加扰 | `g` → `b̃` | 38.211 §6.3.1.1 | Gold 序列，c_init 含 RNTI/小区ID |
| 9 | 调制 | `b̃` → `d` | 38.211 §6.3.1.2 | QPSK/16/64/256QAM(+π/2-BPSK) |
| 10 | 层映射 | `d` → `x` | 38.211 §6.3.1.3 | 单码字→1..4 层 |
| 11 | 变换预编码 | `x` → `y` | 38.211 §6.3.1.4 | DFT-s-OFDM 才做（CP-OFDM 跳过） |
| 12 | 预编码 | `y` → `z` | 38.211 §6.3.1.5 | 层→天线端口，codebook/non-codebook |
| 13 | 映射到 VRB | `z` → 虚拟栅格 | 38.211 §6.3.1.6 | 按 k 增、l 增，跳过 DMRS/PT-RS |
| 14 | VRB→PRB | 虚拟→物理 | 38.211 §6.3.1.7 | 上行恒等（非交织）映射 |

---

## 2.4 两个容易误解的点

1. **「调制」是比特级和符号级的分界线**：步骤 8 加扰其实还是比特运算（异或），但规范把它归在 38.211 的符号级处理里。所以「比特级」严格说是 38.212（步骤 1–7），38.211 从加扰开始。
2. **步骤 11 变换预编码是「可选」的**：CP-OFDM 时**跳过**这一步；只有 `transformPrecoding = enabled`（DFT-s-OFDM）时才做 DFT。Rel-18 后还支持 DCI 动态切换。

## 2.5 与卫星 SDR 收发链逐点对照

| 卫星/通用 SDR 链路 | PUSCH 对应步骤 | 备注 |
|---|---|---|
| CRC 校验 | 步骤 1（发）/ 收端验 CRC | 多项式与长度由 A 定 |
| 信道编码（LDPC/Turbo） | 步骤 2–5 | NR 用 LDPC 基图+提升，速率匹配是环形缓冲 |
| 加扰 | 步骤 8 | 用 Gold 序列，c_init 绑定 RNTI |
| 星座映射 | 步骤 9 | 规范查表，归一化因子写死 |
| 空分复用/预编码 | 步骤 10、12 | 层↔天线端口映射 |
| (单载波) DFT 扩展 | 步骤 11 | DFT-s-OFDM 特有，为降 PAPR |
| 子载波映射 | 步骤 13、14 | 摆到资源栅格，跳过参考信号 |
| IFFT + 加 CP | (38.211 §5.3，链外) | OFDM 基带生成 |

**结论**：PUSCH 链 = 你熟悉的收发链，把每步「参数化 + 标准化」。接下来两章（03、04）逐步骤拆解 + 给 C++ 实现。
