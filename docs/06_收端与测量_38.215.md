# 06 · 收端视角与 38.215 测量

> 目标：补齐收端链路（第 03/04 章是发端），并讲清 38.215 的物理层测量。
> 发端是「查表 + 公式」，收端是「估计 + 迭代译码」——难度主要在后半段。

---

## 6.1 PUSCH 收端链路（发端的逆过程）

```
天线信号 → 去 CP + FFT (OFDM 解调)
  → RE 解映射（按 DMRS/PT-RS 位置恢复符号）
  → 信道估计（用 DMRS）→ 均衡 → LLR 计算
  → 层解映射 → 解调软比特 → 解扰 → 速率解匹配（软合并）
  → LDPC 译码（迭代）→ 码块级联 → CRC 校验
  → TB 上交给 MAC（+ HARQ ACK/NACK）
```

### 6.1.1 信道估计与均衡（你熟悉的部分）

- **DMRS**（解调参考信号）是收端估信道的「探针」：发端在约定 RE 发已知序列，收端对比收到值 → 估计信道响应 → 插值到数据 RE。
- **均衡**：ZF / MMSE，把「数据符号 × 信道」还原成数据符号。
- 这跟你卫星 SDR 里的导频估计 + 均衡完全同构，只是 DMRS 的时频位置由 38.211 §6.4.1.1 精确规定。

### 6.1.2 LLR 与 LDPC 译码（NR 特有）

- **LLR**（对数似然比）：把均衡后的复符号按星座「软判决」成每个比特的可信度，而不是硬判 0/1。
- **LDPC 译码**：迭代的置信传播（belief propagation）—— 变量节点 ↔ 校验节点来回传消息，直到收敛或达最大迭代次数。
- **速率解匹配**：把被打孔/跳过的位置填「0 可信度」（LLR=0），恢复完整码字。
- **HARQ 合并**：重传的 LLR 与之前存储的 LLR 相加（软合并），再译码，收益巨大。

> 这也是 LDPC 相比 Turbo 的一大工程优势：软信息天然适合 SIMD/GPU 并行（第 07 章的 AMX 加速正为此）。

## 6.2 38.215 物理层测量

38.215 定义 UE 要上报的测量量，供移动性/链路自适应决策：

| 测量量 | 定义（简化） | 用途 |
|---|---|---|
| **RSRP** | 参考信号（SSB/CSI-RS）的每 RE 平均接收功率 | 覆盖/移动性 |
| **RSRQ** | `N·RSRP / RSSI`（RSSI 是总接收功率） | 质量 + 负载 |
| **SINR** | 信号 / (干扰 + 噪声) | 链路自适应、MCS 选择 |

- 测量对象：**SSB**（同步信号块）或 **CSI-RS**（信道状态信息参考信号）。
- 上报：L1-RSRP 由 CSI 上报（38.214 §5.2），L3 滤波后由 RRC 上报。

> 物理层测量是「数字孪生/信道建模」岗位的入口——你要能理解并仿真这些量的统计特性（第 08 章扩展）。

## 6.3 发端 vs 收端：难度分布

| 阶段 | 发端 | 收端 |
|---|---|---|
| 编码/译码 | 查表直通 | 迭代 BP，最吃算力 |
| 调制/解调 | 查表 | LLR 软判决 |
| 预编码/均衡 | 查表 | 信道估计 + MMSE |
| 时序 | 严格按 DCI | 盲检 PDCCH + 跟踪 |

**一句话**：发端把 03/04 章搞懂就够了；收端的 LDPC 译码和信道估计，才是「性能优化 + SIMD 加速」的主战场——这也是岗位 JD 里强调 AVX-512/AMX/SVE 的原因。
