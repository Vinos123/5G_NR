# 00 · 导读：如何读 3GPP 物理层规范（38.211–38.215）

> 目标：给你一张「地图」，让你第一次翻开 38.211 时知道自己在哪、该往哪看、那些符号是什么意思。

---

## 0.1 这五本规范各自负责什么

3GPP 把「物理层」拆成五本规范，**分工清晰、各司其职**。读之前先记住这个分工，就不会在错误的规范里找东西：

| 规范 | 全名 | 一句话职责 | 你会在里面找什么 |
|---|---|---|---|
| **38.211** | Physical channels and modulation | 定义**物理信道的「波形与资源」**：资源栅格、OFDM/DFT-s-OFDM、加扰、调制、层映射、预编码、RE 映射 | 一个调制符号怎么摆到资源栅格上 |
| **38.212** | Multiplexing and channel coding | 定义**比特级的「编码与复用」**：CRC、LDPC/Polar、码块分段、速率匹配、级联、控制信息复用 | 一个 TB 怎么变成码字比特 |
| **38.213** | Physical layer procedures for control | 定义 **UE 的「控制类」过程**：PDCCH/DCI 检测、功控、HARQ 时序、UCI/CSI 上报、PRACH | UE 怎么被告知「什么时候、发什么、发多大功率」 |
| **38.214** | Physical layer procedures for data | 定义 **UE 的「数据类」过程**：资源分配、MCS 表、TBS 确定、PDSCH/PUSCH 处理、CSI 参考 | 具体这个 TB 多大、用哪块资源、什么码率 |
| **38.215** | Physical layer measurements | 定义**物理层测量**：RSRP、RSRQ、SINR 等 | UE 怎么测信号质量并上报 |

**记忆口诀**：211 = 波形与资源，212 = 编码与复用，213 = 控制过程，214 = 数据过程，215 = 测量。

### 关键认知：规范是「分层分步」写的

一次 PUSCH 发送，规范把它拆成两条正交的流水线，分别写在两本书里：

```
38.212  (比特级 / bit-level)                38.211  (符号级 / symbol-level)
─────────────────────────────              ─────────────────────────────
Transport Block (TB, 来自 MAC 层)          modulation symbols
      │                                            │
   CRC 附加                                    加扰 scrambling
   LDPC 基图选择                               调制 modulation
   码块分段 + CRC                               层映射 layer mapping
   LDPC 编码                                    变换预编码 DFT-s-OFDM
   速率匹配                                    预编码 precoding
   码块级联                                     VRB 映射 → PRB 映射
   数据/控制复用 (UCI)                         → 交给 OFDM 基带生成
      │
   codeword bits ────────────────────────────→ ┐
                                               (两段在「调制」处衔接)
```

- **38.212 输出 = 一串码字比特**（`f(k)`），直到调制前都是比特。
- **38.211 从调制开始**，把比特变成复数符号、再摆到资源栅格、再生成基带波形。

> 这正是你熟悉的卫星/通用 OFDM 链路，只是 3GPP 把「编码」和「波形」分别放进两本书，并且每一步的参数都用一个 `Table` 或 `clause` 精确定义死了。

## 0.2 规范内部的结构：clause 怎么定位

3GPP 规范的正文用**多级编号**组织，形如 `6.3.1.4`：

- 第 **1 级**（如 `6`）= 章，通常是「Uplink / Downlink」这样的功能区。
- 第 **2 级**（如 `6.3`）= 某条物理信道（`6.3` 是 PUSCH）。
- 第 **3 级**（如 `6.3.1`）= 该信道的处理（`6.3.1` 是 PUSCH 处理）。
- 第 **4 级**（如 `6.3.1.4`）= 具体某一步（`6.3.1.4` 是 Transform precoding）。

**定位技巧**：当你看到 sharetechnote 说「步骤 11 是变换预编码」，直接找 `38.211 §6.3.1.4`。反过来，任何规范 clause，拆开编号就能读出它在讲什么。

### 38.211 的关键 clause 地图（上行）

```
§4   帧结构与物理资源  (numerology、帧/时隙、RE/RB/CRB/PRB/BWP)   ← 第 01 章
§5   通用函数          (调制映射表、OFDM 基带生成)
§6   上行
  §6.3   PUSCH
    §6.3.1 PUSCH 处理
      §6.3.1.1  Scrambling            加扰
      §6.3.1.2  Modulation            调制
      §6.3.1.3  Layer mapping         层映射
      §6.3.1.4  Transform precoding   变换预编码 (DFT-s-OFDM)
      §6.3.1.5  Precoding             预编码
      §6.3.1.6  Mapping to VRB        映射到虚拟资源块
      §6.3.1.7  Mapping VRB→PRB       虚拟→物理资源块
§7   下行 (PDSCH/PDCCH/PBCH，结构对称)
```

### 38.212 的关键 clause 地图（上行）

```
§5   信道编码 (通用)
  §5.1  CRC 计算      ← 定义 CRC24A/24B/24C/16 多项式
  §5.2  码块分段 + 码块 CRC
  §5.3  信道编码       §5.3.1 Polar / §5.3.2 LDPC
  §5.4  速率匹配
§6   上行传输信道与控制信息
  §6.2  UL-SCH (上行共享信道，即 PUSCH 数据)
    §6.2.1  TB CRC 附加
    §6.2.2  LDPC 基图选择
    §6.2.3  码块分段 + 码块 CRC
    §6.2.4  信道编码 (LDPC)
    §6.2.5  速率匹配
    §6.2.6  码块级联
    §6.2.7  数据与控制(UCI)复用
```

> **重要**：`§6.2.1–6.2.7` 这 7 个 clause **恰好对应 PUSCH 的步骤 1–7**。这不是巧合——规范就是按处理顺序写的。所以「读规范」最省力的办法，就是**沿着一条信道的处理链顺序读对应 clause**。

## 0.3 记号约定（读规范前必须先认识）

3GPP 规范有一致的符号约定。以下是最常用、你必须一眼认得的：

| 记号 | 含义 | 例子 |
|---|---|---|
| `a`, `A` | 比特数 / 比特序列 | TB 大小 `A`，码块大小 `K` |
| `b(i)` | 加扰前的码字比特 | 38.212 输出 |
| `b̃(i)` | 加扰后的比特 | 38.211 §6.3.1.1 |
| `d(i)` | 调制后的复数符号 | 层映射前 |
| `x(i)`, `y(i)` | 层映射后 / 变换预编码后 | |
| `z(i)` | 预编码后 | |
| `k`, `l` | 子载波索引 / OFDM 符号索引 | RE 位置 `(k, l)` |
| `μ` | numerology 索引（决定子载波间隔 2^μ·15 kHz） | μ=0→15 kHz |
| `N_RB`, `N_RB^μ` | 资源块数 | |
| `n_RNTI` | UE 无线网络临时标识 | 加扰初始化用到 |
| `N_ID^cell` | 物理小区 ID | 加扰初始化用到 |
| `Q_m` | 调制阶数 (2/4/6/8) | QPSK=2, 256QAM=8 |
| `ν` (nu) | 层数 | 1–4 (PUSCH) |
| `⌈ ⌉`, `⌊ ⌋` | 向上/向下取整 | TBS 计算里大量出现 |
| `mod` | 取模 | |

**一个高频陷阱**：`b(i)` vs `b̃(i)`（b-tilde，加扰后）——sharetechnote 和规范的图里经常混用 `b`，但规范里加扰前是 `b(i)`、加扰后是 `b̃(i)`。读公式时先看清是哪个。

## 0.4 读规范的标准套路（强烈建议养成）

1. **先看 clause 标题**，判断它属于「比特级」还是「符号级」。
2. **看输入/输出**：每个 clause 开头通常写「input is `X`, output is `Y`」。
3. **找公式或 Table**：规范用公式（如加扰的 `c_init` 表达式）或查表（如调制映射表）定义行为。
4. **对照参数来源**：公式里的参数（如 `n_ID`）常来自 38.331 RRC 配置——sharetechnote 的 RRC Parameters 区就是干这个的。
5. **动手验证**：把公式翻译成 C++，用一个小例子跑一遍，和规范/ MATLAB 对得上，才算真懂。

## 0.5 与你的卫星通信 SDR 背景的对照（建立迁移）

| 你熟悉的（卫星/通用） | 5G NR 对应 | 主要差异 |
|---|---|---|
| 单载波或多载波调制 | OFDM / DFT-s-OFDM | 引入了 numerology、BWP、灵活的资源栅格 |
| LDPC / Turbo / 卷积码 | **LDPC（数据）+ Polar（控制）** | LDPC 用「基图 + 提升」结构，速率匹配是环形缓冲 |
| 固定帧结构 | 灵活 numerology + 时隙格式 | 帧长固定 10ms，但符号/时隙长度随 μ 变 |
| 固定星座映射 | 规范 Table 查表映射 | QPSK/16/64/256QAM + π/2-BPSK，归一化因子写死 |
| 加扰序列 | Gold 序列 | 初始化值 `c_init` 与 RNTI、小区 ID、加扰 ID 绑定 |
| 手动调度 | gNB 通过 **DCI** 动态调度 | 资源/码率/时序全部由 DCI + RRC 决定 |

**结论**：你的 DSP 底子直接复用，需要补的是「3GPP 框架」这层皮。本教程就是帮你快速披上这层皮。
